# Account, sync, history and quota fixes — 2026-09-13

## Changes

- Cloud downloads carry both a Firebase UID and a session generation. Applying
  local records is serialized with cleanup; stale downloads cannot repopulate
  cleared databases. Different sessions do not share an in-flight sync future.
- Cleanup now opens each Hive box with its actual model type, propagates failures,
  and keeps downloads suspended until the identity transition completes.
- Repository and queue initialization reopens closed boxes. Repository providers
  rebuild when the Firebase UID changes, including after account deletion.
- Encryption-key deletion clears both the cached key and the completed creation
  future, so the next key is newly generated and persisted.
- Meal history is backfilled in 200-document pages, including legacy records with
  no `updatedAt`. Existing 30-day cursors receive a one-time full backfill.
  Later syncs remain incremental. History access in the Pro date picker is no
  longer limited to 90 days, and older selected dates use their actual totals.
- Meal, deletion and settings download failures propagate to the sync coordinator.
  Successful server reads are required before advancing cursors; cached offline
  snapshots cannot claim that cloud changes have been downloaded.
- Voluntary paywall navigation does not wait for tap analytics. Cold-start quota
  reads are safe, and preference writes obtain storage before using it.
- One shared calendar-day rule allows free access to today and the previous 13
  days in both the diary and meal-based metric history.
- The backend charges every free arbitrary-prompt text request against the daily
  Coach allowance, regardless of `purpose`. Pro access and failure refunds remain
  intact. The free planner sample is local and does not consume this allowance.

## Regression coverage

- `test/session_lifecycle_regression_test.dart`: cold start, key rotation,
  reopening singletons, full deletion cleanup, history boundaries, same-UID
  re-login and cleanup racing with cloud-to-local writes.
- `test/cloud_history_regression_test.dart`: 205 legacy meals across pages,
  migration from an existing cursor, observable download failures, and account
  changes during record application.
- `backend/test/ai_text_quota_regression.test.js`: missing/forged purpose labels,
  daily allowance enforcement, refunds and Pro exemption.

## Release notes

Both an app release and a backend deployment are needed. These changes do not
deploy the backend or change store products, pricing, or RevenueCat configuration.
The first successful sync on an existing installation may read more records while
backfilling history; subsequent syncs use the incremental cursor again.

Before production release, smoke-test sign-out, account switching, deletion and
reopening on Android, including a slow connection; verify a real store purchase
and restore. Automated widget checks are not a substitute for device testing.
